# 層3: サーバ仕様 (オンライン対戦)

対象: `tools/gameserver.mjs`
役割: 静的ファイル配信 + WebSocket (`/ws`) によるサーバ権威の対局進行。

## 基本方針
- **サーバ権威**: 手牌・山・和了判定はすべてサーバが持つ。クライアントは「サーバから届いたビュー」を描画し、
  「サーバから来た質問(prompt)」にだけ答える。クライアントが自発的に着手を送っても受理しない。
- **視界の分離**: 各クライアントに送るのは自分の手牌のみ。他家の手牌は送らない (`viewFor`)。
- **CPUの同居**: 人間とCPUは同じ座席構造 (`seat`) で扱う。CPUは `isCpu: true` と専用辞書を持つだけ。

## 部屋 (room) のライフサイクル

```
                 create / join
                      ↓
   [lobby] ──── start (ホストのみ) ────→ [playing]
      ↑                                     │
      │                                     │ 最終局終了
      │      ともだち対戦: ロビーに戻る       │
      └─────────────────────────────────────┤
                                            │ ランク戦: 使い捨て
                                            ↓
                                     [done] → 破棄
```

| 状態 | 説明 | 受け付ける操作 |
|---|---|---|
| `lobby` | 参加募集中 | `join` `addCpu` `start` |
| `playing` | 対局中 | `act` `ready` |
| `done` | ランク戦終了 (即破棄) | なし |

- 部屋コード: `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (紛らわしい0/O/1/I/Lを除く31文字) から4文字 = 923,521通り。
  生成時に既存コードとの重複を確認する (最大100回リトライ)。
- 参加上限: 4人 (CPU含む)。
- `lobby` から全員が抜けた (人間が0になった) 部屋は破棄する。

## メッセージ一覧

### クライアント → サーバ

| イベント | 送信者 | 前提状態 | 成功時 | 失敗時 | 冪等性 |
|---|---|---|---|---|---|
| `create {name}` | 未入室 | — | 部屋生成、`lobby` 配信 | `error` | 2回目は無視 (既に入室済み) |
| `join {code, name}` | 未入室 | 対象部屋が `lobby` かつ4人未満 | 着席、全員に `lobby` | `error` (該当なし/対局中/満員) | 2回目は無視 |
| `rankJoin {name, rank}` | 未入室・未キュー | — | キュー投入、`rankSearching` | — | 同一接続の重複投入は無視 |
| `rankCancel` | キュー中 | — | キューから除去 | — | 何度でも安全 |
| `addCpu` | ホスト | `lobby` かつ4人未満 | CPU着席、`lobby` 再配信 | 無視 | 上限で頭打ち |
| `start {rounds}` | ホスト | `lobby` かつ2人以上 | `playing` へ、対局開始 | `error` (1人) | 対局中は無視 |
| `act {seq, action}` | 質問中の席 | `seq` が現在の `pending.seq` と一致 | 着手を適用 | 不一致なら**破棄** | `seq` 照合により再送・重複は無害 |
| `ready` | 人間の席 | 局間 | 次局へ進む合図 | — | 何度でも安全 |

`rounds` は `[1,2,4]` のみ受理 (それ以外は既定値2)。`name` は改行除去+8文字に丸め、空なら「ななし」。

### サーバ → クライアント

| イベント | 内容 | 送信タイミング |
|---|---|---|
| `lobby` | `{code, players, hostIdx, youIdx}` | 入退室・CPU追加・対局終了後 |
| `rankSearching` | `{queued}` 待機人数 | キュー人数変化時 |
| `rankMatched` | `{players}` 対戦相手名 | マッチ成立時 |
| `state` | `{view}` 自分視点の盤面 | 盤面が動くたび |
| `prompt` | `{seq, kind:"turn"|"claim", ...}` | その席の判断が必要なとき |
| `banner` | `{text, who}` ツモ/ロン/ポン/カン演出 | 宣言時 |
| `roundEnd` | `{result, isLast}` | 局終了時 |
| `gameEnd` | `{standings, lastResult, youIdx, rank}` | 対局終了時 |
| `error` | `{msg}` | 操作が受理できないとき |

`prompt` の中身:
- `kind: "turn"` → `{canTsumo: bool, kanWords: string[]}`
- `kind: "claim"` → `{ron: bool, ponWords: string[]}`

## 進行の流れ (1局)

```
startRound → [ツモ] → prompt(turn) → 着手適用 → [捨て牌]
                ↑                                  ↓
                └── passClaims ←── prompt(claim) ──┘
                                    (ロン→ポンの順)
```

- ツモ後の選択でカンを選んだ場合は、補充してから再び `prompt(turn)` に戻る。
- 捨て牌後は、捨てた人の**次の席から反時計回り**に全員のロン判定 → 次にポン判定。
  最初に成立した1人だけが権利を得る (**頭ハネ**)。

## タイムアウト

| 対象 | 時間 | 期限切れの動作 |
|---|---|---|
| 手番 (`prompt turn`) | 60秒 | CPUと同じ思考で自動的に1枚捨てる。本人に `banner{時間切れ}` |
| 鳴き (`prompt claim`) | 20秒 | パス扱い |
| 局間の `ready` 待ち | 12秒 | 全員の応答を待たずに次局へ |
| ランクマッチング | 10秒 | 4人に満たなければCPUで埋めて開始 |

## 切断と再接続

現在の挙動:
| タイミング | 動作 |
|---|---|
| `lobby` で切断 | 席を削除。人間が0人になった部屋は破棄 |
| `playing` で切断 | **その席をCPUが引き継ぎ**、対局は継続。保留中の質問は「無応答」として解決 |
| 全員の人間が切断 | 対局を中断 (`aborted`) し部屋を破棄 |

**既知の制約 (未実装)**:
- **再接続は未対応**。切断した本人が戻ってきても席は取り戻せない (新規入室扱い)。
- 引き継ぎCPUの語彙率は一律55%固定で、元プレイヤーの実力は反映しない。
- ランク戦のマッチング後に切断した場合、その席はCPUが打ち切り、**RPは切断者のクライアントには反映されない**
  (RP計算はクライアント側で `gameEnd` 受信時に行うため)。

## ランクマッチング

```
rankJoin → [キュー] ──4人そろう──→ 即マッチ
              │
              └──10秒経過──→ CPUで4人に補充してマッチ
```
- CPUの語彙率は**参加者の平均ランク**から決める (`CPU_VOCAB_BY_RANK`)。
- マッチ成立は `startRankMatch()` 内で同期的に行い、対象4件をキューから取り出してからタイマーを解除するため、
  同時発火による二重マッチは起きない (Node は単一スレッド)。
- 部屋は対局終了で破棄する (使い捨て)。

## 入力の検証 (チート耐性)

サーバが検証している項目:
- 着手は `prompt` に対する応答のみ受理 (`seq` 照合)。手番外の着手は `pending` が無いため破棄。
- `discard`: インデックスが手牌の範囲内かを確認。範囲外なら捨て直しを要求。
- `kan`: サーバが計算した `kanWords` に含まれる語のみ受理。
- `pon`: サーバが計算した `ponWords` に含まれる語のみ受理。
- `ron`: サーバ側で `canRon` を再判定してから受理。
- 受信JSONは4096バイトで打ち切り、パース失敗は無視。

**既知の制約**:
- ランクRP・コイン・図鑑・実績は**すべてクライアントのlocalStorage**にあり、サーバは関与しない。
  改ざん可能であり、あくまでローカルの記録として扱う。競技性のあるランキングを名乗らないこと。
- 部屋コードの総当たり試行に対するレート制限が無い。`lobby` 状態の部屋にしか入れないため影響は限定的だが、
  公開運用するなら接続あたりの `join` 試行回数を制限すべき。
- WebSocket接続数の上限・IPあたりの制限が無い。
